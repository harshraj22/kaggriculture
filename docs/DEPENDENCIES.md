## Runtime — must exist inside the submission sandbox

| Package | Why | Notes |
|---|---|---|
| `kaggle-environments` | `agentlib/game/config.py` re-exports `CROPS`, `ANIMALS`, `MARKET_PARAMS`, `SHOPS`, `LAND_ORDER`, `market_price` from the env module | Almost certainly present — Kaggle's runner is what executes the env. **Not yet verified** that it's importable from the *agent* process. |

**Rule: `agentlib/` imports stdlib + `kaggle_environments` only.** No numpy, no pandas —
analysis code that needs them goes in `tools/`.

**Open risk:** if the agent process can't import `kaggle_environments`, every submission
errors out. Cheapest way to settle it is a throwaway submission whose `agent()` tries the
import and reports via agent logs. Worth doing before we depend on this heavily.

## Known install gotchas

**`kaggle-environments` has a very heavy dependency tree.** As of 1.25.9 it declares
`stable-baselines3`, `jax`, `gymnax`, `transformers`, `open_spiel`, `bitsandbytes`,
`litellm`, `accelerate` and friends — several GB, and pip will backtrack for a long time
trying to resolve them.

Kaggriculture itself needs none of that. If the full install is painful, use the light path:

```bash
pip install --no-deps kaggle-environments
pip install Flask jsonschema pydantic requests pyjson5 termcolor tenacity google-auth numpy
```

Some sibling environments (`cabt`, `open_spiel_env`, `werewolf`) will print
"Loading environment X failed" on import — harmless, they're unrelated envs whose optional
deps are missing.

**Version requirement:** kaggriculture ships inside `kaggle-environments`, so you need a
release recent enough to include it. Verify with:

```python
from kaggle_environments import make
make("kaggriculture")     # InvalidArgument("Unknown Environment Specification") = too old
```

If that raises, `pip install -U kaggle-environments` and re-check. Version 1.25.9 does
**not** include the env.
